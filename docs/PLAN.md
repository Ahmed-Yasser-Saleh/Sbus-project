## 1. Project structure

```
SBus.slnx
├─ src/SBus.Domain           ← entities, business rules, Result/Error
├─ src/SBus.Application      ← commands and queries (MediatR), validators, DTOs
├─ src/SBus.Infrastructure   ← EF Core + Npgsql, Identity, background jobs, receipt storage
├─ src/SBus.Web              ← Razor Pages: passenger pages + office panel
└─ tests/
   ├─ SBus.Domain.UnitTests
   ├─ SBus.Application.UnitTests
   ├─ SBus.Application.SubcutaneousTests
   └─ SBus.Tests.Common
```

- .NET 10, local PostgreSQL 18, a database named `sbus`.
- Times are stored in UTC and shown in Cairo time (`Africa/Cairo`, with daylight saving time).
- No Hangfire: expired holds are closed by a simple `BackgroundService` every minute, and trips are generated by another one every hour.

## 2. Tables

### Setup (configured once by the office)

| Table | Key columns | Notes |
|---|---|---|
| `Stops` | Name, Description, IsActive | Every pick-up and drop-off point |
| `RouteStops` | Direction, StopId, Order, MinutesFromStart | The order of stops in each direction, and the approximate time from departure so the ticket can say "the bus reaches you around 6:40" |
| `SeatLayouts` | Name, Rows, Columns, DriverRow, DriverColumn | The minibus layout |
| `LayoutSeats` | SeatLayoutId, SeatNumber, Row, Column | Each seat and its position, using the numbers printed on the real seats |
| `Buses` | PlateNumber, SeatLayoutId, IsActive | |
| `Drivers` | Name, PhoneNumber, IsActive | |
| `Schedules` | Direction, DepartureTime, Price, BusId, DriverId, IsActive | The fixed daily departures |

### Daily operations

| Table | Key columns | Notes |
|---|---|---|
| `Trips` | ScheduleId, Direction, ServiceDate, DepartureTime, DepartureAtUtc, Price, BusId, DriverId | An actual trip on a given day, generated from `Schedules` for the days ahead. Unique on (ScheduleId, ServiceDate). The price is copied at generation time, so a price change does not alter trips that were already booked |
| `Bookings` | TripId, PublicToken, PassengerName, PhoneNumber, PickupStopId, DropoffStopId, PricePerSeat, Amount, Status, Source, HoldExpiresAtUtc, ReceiptFileName, ReceiptSubmittedAtUtc, ConfirmedAtUtc, ClosedAtUtc, CancelledBy, RejectionReason | `PublicToken` is the secret code in the ticket link. `Source` is Online or Office |
| `BookingSeats` | BookingId, TripId, SeatNumber, IsActive | **Partial unique index on (TripId, SeatNumber) WHERE IsActive**, which is what prevents double booking. On cancellation or expiry `IsActive = false`, so the seat frees up and the history stays |

Office users: ASP.NET Core Identity.

### Booking states

```
HoldPendingPayment ──receipt uploaded──► AwaitingConfirmation ──office confirms──► Confirmed
       │                                        │                                     │
  hold expired                           office rejects                  cancelled (passenger/office)
       ▼                                        ▼                                     ▼
    Expired                                 Rejected                              Cancelled
```

- The seat is held in every state except Expired, Rejected and Cancelled.
- Once the receipt is uploaded the booking **does not expire by itself**: the passenger has paid, so the decision belongs to the office.
- An office booking for a caller starts as Confirmed.

## 3. Screens

### Passenger (no sign-in)

1. **Home**: choose the direction and the day, and see the trips and the number of free seats on each.
2. **Trip**: the seat map (free / taken / your pick), name, mobile number, pick-up and drop-off points.
3. **Ticket** `/t/{token}`: status, seats, trip, approximate time at the passenger's stop, the InstaPay details with a countdown and the receipt upload while payment is pending, the driver's number (shown only once the booking is confirmed), and a cancel button.

### Office (with sign-in)

1. **Today**: the day's trips and how many seats are booked on each.
2. **Payment review**: bookings waiting for confirmation, the transfer screenshot, and confirm / reject buttons.
3. **Trip details**: the seat map, the passenger manifest (name, number, seat, stop) with a print button, booking for a caller, cancellation, and changing the bus or driver.
4. **Settings**: stops and their order, schedules and prices, buses and seat layouts, drivers.

## 5. Open questions (each has a default; change it if it is wrong)

| Question | Default |
|---|---|
| How many seats can a passenger book at once? | Up to 4 seats per booking |
| How long is a seat held before the receipt is uploaded? | 15 minutes |
| Until when can a passenger cancel online? | Up to 2 hours before the trip; after that they call the office |
| How far ahead does booking open? | 7 days |
| Stop names, times and prices | Demo data until the real ones are available |
| Minibus layout | 14 seats (Toyota HiAce) until the real seats are photographed |
| InstaPay address shown to passengers | A placeholder in the settings |
| Transfer screenshots | Stored in a folder on the machine **outside** `wwwroot`, so nobody can open them without the office sign-in |
